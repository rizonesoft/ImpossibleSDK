# Plan Review: D06 T01 §2 (Deflate)

## Scope and Deliverables (Revised after Plan Review 2)

Implement a portable, freestanding, zero-heap-allocation, no-float streaming DEFLATE (RFC 1951), zlib (RFC 1950), and gzip (RFC 1952) compressor in `parts/deflate/deflate.h` and `parts/deflate/deflate.c`, depending only on `parts/checksum` (`im_crc32_update`, `im_adler32_update`), registered in `parts.json`, `cmake/ImpossibleSDK.cmake` (both sources and PUBLIC include directory `parts/deflate`), `CMakeLists.txt` (`deflate-tests` CONSOLE TIER 0), and documented in `docs/guide/drawing.md` (with `docs/guide/own-program.md` reviewed).

## Architecture and API

1. **Header (`parts/deflate/deflate.h`):**
   - Formats: `im_deflate_format`: `IM_DEFLATE_RAW = 0`, `IM_DEFLATE_ZLIB = 1`, `IM_DEFLATE_GZIP = 2`.
   - Efforts: `im_deflate_effort`: `IM_DEFLATE_FAST = 0` (zlib level 1), `IM_DEFLATE_BALANCED = 1` (zlib level 6), `IM_DEFLATE_BEST = 2` (zlib level 9).
   - Named status codes (`im_deflate_status`): `IM_DEFLATE_OK = 0` (init succeeded or stream finished and trailer emitted), `IM_DEFLATE_NEED_INPUT = 1`, `IM_DEFLATE_OUT_FULL = 2`, `IM_DEFLATE_BAD_ARG = 3`.
   - Exact API contracts: `in == NULL` allowed iff `in_len == 0`; `out == NULL` allowed iff `out_cap == 0`; optional `in_used`/`out_used` always written on every return (`0/0` on `BAD_ARG` or post-`OK`); `is_eof` latches whenever `in_pos == in_len` (including empty `is_eof=true` calls during header drain, so subsequent `is_eof=false` retries finish cleanly); post-`OK` call returns `OK` (`0/0`) if `in_len == 0` or `BAD_ARG` if `in_len > 0`; `im_deflate_all(im_deflate *st, ...)` takes caller-owned `st` and writes emitted byte count to `*out_len` on `OK` and `OUT_FULL` (`0` on `BAD_ARG`).
   - Accounted fixed memory (< 512 KiB state, < 1,000,000 bytes decimal total including inflater, I/O buffers, and verified helper stack frames <= 1024 bytes via `-Wframe-larger-than=1024`, zero heap allocation): all Huffman scratch arrays live inside `struct im_deflate`; `prepare_block` uses closed-form RFC 1951 §3.2.6 fixed codes with zero stack table and `encode_code_lengths` indexes `lit_len`/`dist_len` directly.

2. **Match History, Window Slide, and Determinism (`parts/deflate/deflate.c`):**
   - `head[]` and `prev[]` store `pos + 1` (`0` = empty sentinel), shifted by saturating subtraction `v > 32768 ? v - 32768 : 0` on slide.
   - Match candidates enforce `cand < pos` and `1 <= dist <= min(32768, valid_history)`.
   - `IM_DEF_MAX_BLOCK_RAW = 32000` guarantees `block_start >= 32768` before `strstart` ever reaches `65536 - 262`, so `window[block_start..strstart)` always retains the full live block across slides for stored-block fallback.
   - `IM_DEF_MIN_LOOKAHEAD = 262` (`258 + 3 + 1`) is retained whenever `!eof_latched` so greedy and lazy matching see identical lookahead bytes across arbitrary input splits.
   - Non-final (`BFINAL=0`) blocks flush ONLY when `!prev_match_avail && lookahead > 0` and block threshold (`n_tokens >= 32766` or `strstart - block_start >= 32000`) is reached; final (`BFINAL=1`) block flushes ONLY when `eof_latched && lookahead == 0`. Both EOF schedules produce byte-for-byte identical output.
