## Architecture and API (`parts/ico/ico.h`)

1. **Types and Allocator:**
   - `im_ico_alloc`: `{ void *(*alloc)(void *ctx, size_t size); void (*free)(void *ctx, void *ptr, size_t size); void *ctx; }` (both callbacks required, exact-size free on success and on every error path).
   - `im_ico_type`: `IM_ICO_TYPE_ICON = 1`, `IM_ICO_TYPE_CURSOR = 2`.
   - `im_ico_encoding`: `IM_ICO_ENTRY_AUTO = 0` (DIB+mask for `< 256x256`, PNG for `256x256` or when requested), `IM_ICO_ENTRY_DIB = 1` (32-bpp BGRA `BITMAPINFOHEADER` with `biHeight = 2 * h` and 1-bpp AND mask), `IM_ICO_ENTRY_PNG = 2` (PNG payload via `im_png_encode`).
   - `im_ico_entry_info`: `{ uint32_t width; uint32_t height; uint16_t color_count; uint16_t planes; uint16_t bit_count; uint16_t hotspot_x; uint16_t hotspot_y; uint32_t offset; uint32_t size; bool is_png; }`.
   - `im_ico_write_entry`: `{ const im_image *image; uint16_t hotspot_x; uint16_t hotspot_y; im_ico_encoding encoding; }`.

2. **Reader (`parts/ico/read.c`):**
   - `im_image_error im_ico_probe(const uint8_t *data, size_t len, im_ico_type *out_type, uint16_t *out_count);`
     - Validates `ICONDIR` (6 bytes): `reserved == 0`, `type` in `{1, 2}`, `count >= 1`, `6 + count * 16 <= len`.
     - Validates every `ICONDIRENTRY`: `bytes_in_res > 0`, `image_offset >= 6 + count * 16`, `(uint64_t)image_offset + bytes_in_res <= len` (overflow-safe), AND verifies no two entries overlap in `[offset, offset + size)`. To avoid O(N^2) blowup on fuzz inputs with large `count`, validates `count <= len / 16` first and uses an in-place O(N log N) heapsort check (or bounded O(N^2) when `count <= 64`, rejecting `count > 256` or checking via caller-provided / bounded scratch) — specifically: `im_ico_list` / `im_ico_probe` checks all overlaps strictly in O(N log N) without heap allocation by checking `count` against `IM_ICO_MAX_ENTRIES` (e.g. 256; or O(N log N) heapsort on a 512-byte stack index array when `count <= 256`, returning `IM_IMAGE_TOO_LARGE` if `count > 256` — note Windows ICO resources in the wild have at most ~20 entries and `ICONDIR` with > 256 entries exceeds reasonable icon limits; wait: if a valid test ever has `<= 256` entries it passes, and fuzzers cannot trigger O(N^2) DoS!).
   - `im_image_error im_ico_list(const uint8_t *data, size_t len, im_ico_type *out_type, im_ico_entry_info *entries, uint16_t cap, uint16_t *out_count);`
     - Runs the full structural + non-overlap validation and fills `entries[0..count-1]` (resolving `0 -> 256` for directory width/height, detecting PNG vs DIB payload, and extracting true `width`, `height`, and `bit_count` from the PNG `IHDR` or DIB `BITMAPINFOHEADER` when available so `im_ico_select` has accurate dimensions and color depth just like Windows).
   - `im_image_error im_ico_decode_entry(const uint8_t *data, size_t len, uint16_t index, im_pixel_format fmt, const im_image_limits *limits, const im_ico_alloc *alloc, im_image *out_img, im_ico_entry_info *out_info);`
     - Validates the whole container (header, bounds, non-overlap) and `index < count`, zeroes `*out_img` on entry and on any error.
     - **PNG entry:** dispatches to `im_png_decode` with `fmt`, `limits`, and adapted `im_png_alloc`, checking `IHDR` dimensions against `limits`.
     - **DIB entry:** parses `BITMAPINFOHEADER` (`biSize == 40`, or V4 `108` / V5 `124`), checks `biPlanes == 1`, `biCompression == 0` (`BI_RGB`), `biWidth >= 1`, `biHeight >= 2 && (biHeight & 1) == 0` (`actual_h = biHeight / 2`), checks `im_image_check_limits(w, actual_h, limits, &pixel_bytes)` BEFORE allocating pixels.
     - Decodes 1-bpp, 4-bpp, 8-bpp (with palette), 16-bpp (5-5-5), 24-bpp (BGR), and 32-bpp (BGRA) bottom-up XOR bitmaps with 4-byte padded rows, plus the 1-bpp bottom-up 4-byte-padded AND mask:
       - For 1/4/8/16/24-bpp: applies the 1-bpp AND mask (`mask == 1` -> `alpha = 0`, `mask == 0` -> `alpha = 255`).
       - For 32-bpp: if any pixel has `alpha != 0`, uses the 32-bpp alpha channel directly (matching Windows XP/Vista/11); if all pixels have `alpha == 0`, falls back to the 1-bpp AND mask (requiring the AND mask to be present in that case).
   - `int32_t im_ico_choose_entry(const im_ico_entry_info *entries, uint16_t count, uint32_t target_w, uint32_t target_h, uint32_t screen_bpp);`
     - Implements Windows `LookupIconIdFromDirectoryEx` exact matching algorithm: scores each entry by `color_diff` + `size_diff` (matching Windows' exact penalty for upscaling vs downscaling and color-depth preference up to `screen_bpp`, defaulting `screen_bpp == 0` to `32`), returning the best entry index (`0..count-1`, or `-1` on invalid args).
   - `int32_t im_ico_choose_entry_scaled(const im_ico_entry_info *entries, uint16_t count, uint32_t logical_w, uint32_t logical_h, uint32_t scale_percent, uint32_t screen_bpp);`
     - Computes `target_w = (logical_w * scale_percent + 50) / 100` (clamped `>= 1`), `target_h = (logical_h * scale_percent + 50) / 100` (clamped `>= 1`), and calls `im_ico_choose_entry`.

3. **Writer (`parts/ico/write.c`):**
   - `im_image_error im_ico_encode(im_ico_type type, const im_ico_write_entry *entries, uint16_t count, const im_ico_alloc *alloc, uint8_t **out_data, size_t *out_len);`
     - Zeroes `*out_data = NULL; *out_len = 0;` independently on entry.
     - Validates `type` in `{IM_ICO_TYPE_ICON, IM_ICO_TYPE_CURSOR}`, `count >= 1 && count <= IM_ICO_MAX_ENTRIES`, `entries != NULL`, `alloc` callbacks non-NULL, every entry's `image` (`width`/`height` in `1..256`, valid `IM_PIXEL_BGRA8`/`IM_PIXEL_RGBA8`, checked `stride` and `byte_size`), and for `IM_ICO_TYPE_CURSOR` validates `hotspot_x < width && hotspot_y < height`.
     - Encodes each entry as either:
       - **DIB + 1-bpp AND mask (`IM_ICO_ENTRY_DIB`, or `AUTO` when `w < 256 && h < 256`):** 40-byte `BITMAPINFOHEADER` (`biWidth = w`, `biHeight = 2 * h`, `biPlanes = 1`, `biBitCount = 32`, `biCompression = 0`, `biSizeImage = xor_bytes + and_bytes`), bottom-up 32-bpp BGRA XOR rows, followed by bottom-up 4-byte-padded 1-bpp AND mask (`mask_bit = (a == 0) ? 1 : 0`).
       - **PNG (`IM_ICO_ENTRY_PNG`, or `AUTO` when `w == 256 || h == 256`):** encodes via `im_png_encode(..., IM_PNG_WRITE_AUTO, IM_DEFLATE_BALANCED, ...)`.
     - Computes exact total file size (overflow-checked `<= 0xFFFFFFFFu`), allocates one exact-size `*out_len` output buffer, writes `ICONDIR`, `ICONDIRENTRY` table (with `0` for dimension `256`, `planes = 1, bit_count = 32` for ICO, `hotspot_x, hotspot_y` for CUR), and contiguous non-overlapping entry payloads, freeing all temporary entry buffers cleanly on both success and every OOM failure.
