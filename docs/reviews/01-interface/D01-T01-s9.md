§9 has gaps. Its proposed tests can pass while a removed node leaves stale pixels, a hover repaints the whole window, or an animation never wakes an idle window.

1. **P1. Removed and hidden subtrees can leave stale pixels.** Path: An application destroys a painted subtree, replaces a child, or collapses and reopens a parent between paints. Evidence: traced `ui/tree.c:115`, `ui/tree.c:198`, and `ui/tree.c:216`. Removal unlinks the child, destruction frees it, and replacement takes it out of the live traversal. A later collector cannot recover old bounds stored only on that node. Also, `ui/layout.c:1003` can move descendants without a local arrange mutation, and `ui/layout.c:1012` returns on collapse without clearing every descendant rectangle. Require damage to survive detachment, compare effective visible bounds after layout with the last painted frame, and test destroy-before-collect, replace, ancestor movement, and collapse/reopen.

2. **P1. Damage uses two coordinate systems without a conversion contract.** Path: A button moves or changes colour on a 150% display, or a window moves between monitors. Evidence: traced `ui/layout.c:1023` and `ui/layout.c:1066` through `docs/guide/first-window.md:47`. The tree stores arranged coordinates, while the canvas and Windows update box use device pixels. §9 specifies outward rounding but does not say where to apply scale. Require scaling both edges before rounding and clipping, plus a full repaint when the backing image’s scale changes. A fractional, partly offscreen rectangle at 150% should have an independently calculated expected pixel box.

3. **P1. The scheduler lacks a production wake-up and final-frame path.** Path: A pointer starts a brush transition and then stays still, or reduced motion snaps the transition while it is running. Evidence: traced `ui/host.h:63`, `ui/host.h:74`, `src/window.c:108`, `ui/states.h:100`, `ui/states.h:109`, and `ui/states.h:131`. The host supplies a clock but has no frame-request callback. Windows blocks in `GetMessageW`, and the button can change colour without changing tree geometry. Define who requests and delivers the first and subsequent frames, how a state change dirties its control, and how the final sampled value reaches the screen. Test a real transition through settlement and a reduced-motion snap, with no further input. Counting requests across 625 test-driven ticks cannot establish that production wakes or sleeps correctly.

4. **P2. The hover test bypasses the event path that requests a full redraw.** Path: A pointer handler invalidates one button and returns `true` as documented. Define how explicit damage interacts with the existing return value and preserve the full-repaint behavior for existing callers. Drive the test through pointer input. Record the pixels the paint callback actually visits, since the examples at `docs/guide/drawing.md:19` and `docs/guide/first-window.md:15` write every pixel regardless of `rcPaint`.
